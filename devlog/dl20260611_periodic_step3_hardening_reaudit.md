# 2026-06-11 - Periodic Step 3 hardening re-audit

Read-only Codex re-audit of the Step 3 hardening fixes for deterministic
periodic node-pair restoration.

## Scope

- Audited 3k layer-node pair registration in `ThinShellFactory`.
- Audited 3l proto periodicity Hesse reconstruction and final-state guard.
- Audited 3m interface-duplicate pair registration.
- Swept all rank-0 `Node::set_periodic()` sites between the initial node-pair
  backup and Maxwell's final periodicity update.
- Spot-checked `todo/periodic_thin_cut_continuity_fix.md` for staleness.

## Findings

- The registration sweep is clean for the current rank-0 cut/thin-shell path:
  every post-backup/pre-restore `Node::set_periodic()` site has a matching
  `add_node_pair_to_backup()` call.
- Thin-shell layer-node registration is not statically guaranteed to stay on
  the periodic Hesse planes. Layer nodes are generated by extrusion along
  facet-derived shell normals, with no projection onto the periodic plane, so
  `add_node_pair_to_backup()` can still fail for oblique geometry.
- Proto Hesse reconstruction still lacks active validation for exactly three
  plane nodes and nondegenerate plane normals. The helper normalizes
  `cross(Q,R)` without the guard used by the factory path.
- Interface duplicate registration is now structurally sound for the current
  flow: duplicate pairs are registered once, the release lookup path fails
  loudly through `Map::operator()`, and no new `is_periodic()` consumer was
  found before the final restore.

## Plan follow-up

The plan should be softened from "3k/3l/3m closed" to "registration implemented;
reproducer and Hesse-validation checks still pending." Step 4 should include an
explicit runtime check that periodic thin-shell layer-node registration does not
trip the Hesse-plane classification on the target reproducer.
