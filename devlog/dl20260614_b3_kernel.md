## Key findings

- **HEADLINE 1 - nonlinear driving:** SolverAlgorithm{Direct,NewtonRaphson,Picard}. The kernel fully
  implements a consistent-tangent Newton-Raphson solve (J*delta=r; assemble_newton adds the IWG dJ/dx,
  also condensed as tTdJT; Maxwell computes the tangent terms dKdX_times_x etc.) AND a relaxed Picard
  solve, with adaptive omega relaxation + stagnation/divergence handling. BUT the Newton path is
  **DORMANT for the magnetic equation**: every timestep forces set_algorithm(Picard)
  (cl_FEM_Controller.cpp:101,184,257), the residual-based promotion ("tolerance switch") is commented out
  (1196-1200), and no runtime path re-promotes the magnetic equation to Newton (Codex confirmed
  tree-wide). Thermal reapplies its config algorithm (1387-1393); magnetic has no analogue. So the
  magnetic nonlinear solve runs effectively Picard with Newton wired-but-unused - directly relevant to
  the Maxwell E-J power-law tangent question.
- **HEADLINE 2 - static condensation:** Tmatrix::project computes T^T*A*T (stiffness) and T^T*A (rhs);
  applied per-element during assembly to J, rhs B, AND the Newton term dJdx consistently
  (cl_FEM_DofManager.cpp:471-541, 652-791). ONE shared per-element T-matrix machinery for both
  hanging-node DOFs (mesh sources via create_dofwise_t_matrices_master) and cohomology-cut/abstract DOFs
  (CutSet sources {abstract,original} weight 1 -> phi'=phi+I). Codex tightening (verified): the
  multi-interface edge cascade is linear-edge-only behind BELFEM_ASSERT (number_of_dofs()==1,
  DofData:3906,3915) that compiles away under NDEBUG - a release robustness gap.
- **Calculator:** mB = J^-1 dNdXi gradient operator (mInvJ inverse Jacobian); curl C delegated to the
  Nedelec EdgeFunction. Not tested.
- **Assembly:** per-element scatter by dof->index(); free/fixed(Dirichlet) split into A/J vs D matrices;
  jedi-force enforcement into E/I; Group abstraction (elements+IWG+integration).
- **Solve/time:** SolverData owns belfem::Solver, dispatches by type (the untested default SuperLU path
  runs here); ARPACK eigensolve via EigenValues; time loop shifts history fields (shift_fields), dt in
  voltage-BC RHS.
- **Tests: NONE at ctest level** - no assembly/patch/condensation/Calculator/convergence/timestep test.
  Verified only via example apps (staticheat/poisson/petsctest/hangingnodes) + end-to-end Maxwell apps.
  The most integration-heavy module has zero unit coverage.
