# Doxygen: publish the module markdown and clear the warning backlog

**Date:** 2026-08-07
**Purpose:** Record how the `*/doc/*.md` documentation was wired into the generated
Doxygen site, and how the warning count was brought from 607 to 16
**Module:** build system, `doc/`, `scripts/`

---

## Starting point

`Doxyfile.in` already listed `*.md` in `FILE_PATTERNS` (twice — once in the main list and
again in a hand-appended tail), and `INPUT` pointed at `src/` with `RECURSIVE = YES`. All
72 module markdown files were therefore already being rendered, but as a flat
alphabetical list of "Related Pages" at machine-generated URLs such as
`md_src_fem_kernel_doc__r_e_a_d_m_e.html`. Three things kept that from being browsable:

1. **The layout file never loaded.** `LAYOUT_FILE = doc/DoxygenLayout.xml` was a relative
   path, but the CMake target runs Doxygen with `WORKING_DIRECTORY
   ${CMAKE_CURRENT_BINARY_DIR}`, so Doxygen reported `failed to open layout file` and
   fell back to the default. The message was lost among 607 other warnings. The file
   would not have worked in any case: `<tab type="pages" relpath="...">` is not a
   navigation mechanism Doxygen implements, and `classhierarchy` is not valid inside
   `navindex` (Doxygen warns about that one explicitly). It has been deleted.
2. **`doc/` was not in `INPUT`.** The repository-level pages — `coding_philosophy.md`,
   `literature_references.md`, `documentation_guidelines.md` — were absent, which is
   exactly what the layout file's "Architecture & Philosophy" tabs pointed at.
3. **No landing page.** `USE_MDFILE_AS_MAINPAGE` was empty.

## Page tree

Doxygen needs two things to build a hierarchy out of markdown: a stable page label, and
`@subpage` directives establishing parent/child. Both are now generated by
`scripts/update_doc_index.py`:

- a `{#anchor}` on the first heading of every page under `doc/` and `src/**/doc/`,
  derived from the path (`src/fem/kernel/doc/README.md` → `{#fem_kernel_index}`). This
  fixes the URL to `fem_kernel_index.html` and gives `@ref` a target.
- `doc/doxygen_nav.dox`, a generated file holding the whole hierarchy.

The hierarchy deliberately lives in the `.dox` file rather than in the markdown. Most
module READMEs already curate a "Documentation Files" section for people browsing the
repository on the web, and `@subpage` directives written into those files would appear
there as literal text. A `.dox` file is invisible to a markdown renderer, so both
surfaces stay clean. Doxygen 1.9.1 will *not* merge a re-opened `@page` (it reports
`multiple use of page label`), so the `.dox` cannot add children to a page defined by a
markdown file; instead it defines one synthetic page per module (titled `src/<path>`)
holding the module README and its detail documents as siblings.

Resulting tree: **BELFEM** → *Module Documentation* → 21 module nodes → 73 pages, plus
the repository-level pages hanging off the landing page. `doc/mainpage.md` is the one
markdown file allowed to carry `@subpage` directives, because it exists only for Doxygen.

The script is idempotent and has a `--check` mode for a hook or CI job. `make doc` runs
it before invoking Doxygen, so a newly added document appears in the navigation without
a manual step.

## Warnings: 607 → 16

Only 20 of the original 607 came from markdown; the rest were in C++ headers.

| Cause | Count | Resolution |
|---|---|---|
| `<number of dimensions>` etc. in `@param` text parsed as an HTML tag | 376 | escaped the angle brackets in 2 interpolation headers; `INHERIT_DOCS` was replicating 16 source lines across every derived class |
| LaTeX continuation lines starting at column 0, dropping Doxygen out of the formula | ~40 | re-attached the lines to the comment block in 6 headers |
| `INCLUDED_BY_GRAPH` exceeding `DOT_GRAPH_MAX_NODES` | 7 | disabled; the graph for `typedefs.hpp` has 362 nodes and is unreadable |
| C++11 extended friend declarations | 4 | `HIDE_FRIEND_COMPOUNDS = YES` (partial) |
| `@param` names not matching the signature | ~35 | corrected in 12 files (see below) |
| partially documented parameter lists | 13 | filled in |
| markdown link and markup defects | 20 | fixed (see below) |

Defects worth naming, because they were latent rather than cosmetic:

- **`cl_Material.hpp`** carried a stray implementation of
  `Material::load_bh_curve( const string &, const string & )` *inside* the class doc
  comment, splitting a bullet list. It was inert, and no such overload exists — the real
  one takes a `BhCurve *`. Removed.
- **`cl_IFG_TET10B.hpp`** never closed its `\f{align}{` block. The defect was masked
  while the formula was already broken by the column-0 continuation lines; fixing those
  exposed it.
- **`powerlaws.hpp`** had the long power-law derivation block attached to `jc_eval`
  instead of `rho_powerlaw`, because it sat immediately above the wrong function. Moved.
- **`materials_contracts_and_invariants.md`** began with a stray `R` character glued to
  its heading (`R# BELFEM Materials …`), so it had no title at all.
- **`cl_Material_Metal.hpp` / `cl_Material_Alloy.hpp` / `cl_Material.hpp`** documented
  `rho` and `lambda` with the pre-unification parameter names `normB` / `angleJxB` (and
  in Alloy, in the wrong order) against signatures reading `( T, B, beta )`. This was the
  documentation half of the argument-order unification that had been left pending.
- **`cl_Bezier.hpp`**, **`cl_IWG_Timestep.hpp`**, **`cl_IWG_Poisson.hpp`**,
  **`cl_FEM_DofManager.hpp`** documented parameters that no longer exist
  (`aX`/`aY` for renamed outputs, `aM`/`aK`/`aN`/`aF` for a signature that now takes only
  the element, `aNumberOfDimensions`, `aMesh`).

Markdown fixes: links pointing at directories (which Doxygen cannot resolve, and which
were already broken on the web because the relative paths were wrong) now point at the
module README; links to `CLAUDE.md` became plain text, since that file is not published;
two `todo/` citations were rewritten as prose, per the rule that documentation does not
cite todos; and one Doxygen 1.9.1 markdown quirk was tracked down by bisection — an
inline code span nested inside `**bold**` breaks its emphasis parser, which was leaving a
`<strong>` open across 370 lines of `circuit_usage_guide.md`.

## Remaining 16 warnings

All are Doxygen parser limitations on valid C++, not documentation defects:

- 9 × doc comments on anonymous comparator structs (`op_Graph_Vertex_*`,
  `op_Node_Index`, `op_Segment_Index`, `cl_GT_ComparisonObjects`). Naming the structs
  would silence them.
- 4 × C++11 extended friend declarations (`friend mesh::GmshReader;`) in `cl_Mesh.hpp`
  and `cl_GT_GasData.hpp`; adding the `class` keyword would silence them.
- 1 × pointer-to-member-function data member in `cl_MeshChecker.hpp`.
- 2 × `@param` merged across same-named overloads of `rho_powerlaw` / `rho_piecewise`.

They were left alone rather than churning headers for a tool artifact. The count is now
a baseline: `WARN_LOGFILE` sends warnings to `<build>/doc/doxygen_warnings.log`, and
`cmake/report_doxygen_warnings.cmake` compares against `16` after every `make doc`,
warning only when the number grows. Silencing the first two groups would allow
`WARN_AS_ERROR`.

## Found but not fixed

`src/physics/materials/cl_Material.hpp` guards its diagnostic pragmas asymmetrically: the
push is under `#if defined(__clang__)` / `#elif defined(__GNUC__)`, but the pop is under
`#ifdef BELFEM_CLANG` / `#elif BELFEM_GCC`. Different macros, and `#elif BELFEM_GCC`
evaluates an undefined macro as 0. Under a compiler where the push fires and the pop does
not, the diagnostic stack is left pushed and `-Wformat`, `-Wunused-variable` and
`-Wunused-parameter` stay suppressed for everything included afterwards. This is a
compilation-behaviour change and was left out of a documentation change set.
