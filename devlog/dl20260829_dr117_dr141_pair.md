# DR-117 + DR-141: phase precedence and the Rule-of-Five hole

**Date:** 2026-08-29
**Purpose:** record the paired circuit-module fix round — the `set_periodic` phase defect
(DR-117) and the implicit-copy hazard on `Solver` / `ElectricalCircuit` (DR-141) — and the
two by-catch findings it produced
**Module:** numerics/sources, circuit, sparse

## What was asked

Christian asked for a list of every debt-register row connected to the circuit module, then
for DR-117 and DR-141 to be fixed as a pair. Nine rows are circuit-connected; three carried
real remaining code work (DR-39, DR-117, DR-141), four were fixed with run gates owed

## DR-117: the register understated its own row

The row was filed as an operator-precedence slip with a `pi^2` error factor, tagged LATENT
on the reasoning that `function_sine` ignores `time_offset` and every shipped deck uses sine.

The first half is true and the conclusion does not follow. `set_periodic` calls
`set_phase( aPhase )`, which already writes BOTH slots correctly — the phase itself and the
`phase/omega` time offset — and then called `set_time_offset` a second time. That setter
back-computes the phase from the offset, so the flagged line did not merely corrupt the
offset: it also overwrote `PHASE` with `aPhase*pi^2`. `function_sine` reads `phase()`.

Sine with a nonzero phase was wrong, by the same factor as everything else. Shipped decks
were unaffected only because they all set `phase : 0`, and `0*pi^2 == 0`. The exposed path
was the ngspice `SIN` phase argument, which converts degrees to radians and hands them
straight to `set_periodic`.

### The filed fix was the wrong fix

The row proposed `(aPhase/(2.0*constant::pi))*aPeriod`. Both auditors rejected it
independently: at `aPeriod == 0` the period setter parks `omega` at `BELFEM_INFINITY`, and
the rewrite's `set_time_offset( 0 )` then evaluates `0 * INFINITY` in its phase write-back.
A probe confirmed the pre-fix tree already returns `phase = -nan` there, and the rewrite
would have preserved it.

The landed fix is to DELETE the line. `set_phase` two lines above is authoritative, the
second write path was redundant as well as destructive, and the NaN goes away as a by-catch.

### Evidence

A standalone probe compiled the pre- and post-fix `cl_SourceFunction.cpp` against the
prebuilt libraries and ran both, rather than reasoning about the arithmetic:

| case | pre-fix | post-fix |
|---|---|---|
| square `T=1, phase=pi/2` offset | `2.46740110` | `0.25000000` |
| phase (both waveforms) | `15.50313834` (= `pi^3/2`) | `1.57079633` |
| sine `f(0)` | `0.20339575` | `1.00000000` |
| sine `T=4, phase=pi` offset | `19.73920880` | `2.00000000` |
| sine `phase=0` (guard) | `0, 0` | `0, 0` |
| square `T=0` phase | `-nan` | `1.57079633` |

`tests/circuit/test_SourceFunction.cpp` pins these in the existing fast circuit binary.
Two assertions from the pre-registration were removed on audit advice: the round-trip
identity is green on the buggy tree (the `pi^2` corruption is self-consistent across both
slots), and no square or sawtooth sample is asserted before the offset — see DR-145.

## DR-141: mechanical, with one split verdict

All four operations deleted on `Solver` and `ElectricalCircuit`, following the DR-142 idiom
rather than the `SpMatrix` one — `SpMatrix` deletes only its constructors and keeps
assignment deliberately, because an empty matrix is a usable assignment target. Neither
class here has an empty state.

The abstract `Circuit` base split the vendors: Codex called it optional and would have
skipped it, Grok called it optional and would do it. Resolved in favour of doing it, because
the row names that header explicitly. The comment states the narrow guarantee it actually
buys, after Grok pushed back on a first draft that overclaimed: a future subclass cannot stay
*implicitly* copyable by forgetting its own declarations; a hand-written copy constructor
that default-initializes the base is still possible.

`Solver mSolver = Solver( SolverType::SUPERLU )` became brace-init, so the member no longer
depends on C++17 guaranteed elision to survive the deleted constructors.

Positive control, executed: `Solver t = s`, `ElectricalCircuit t = c` and a `static_cast`
move are all `use of deleted function` errors, while ten consumer TUs still syntax-check
clean under `-std=gnu++17`.

## By-catch

**DR-145 filed** — `std::fmod` keeps the sign of its dividend, so `square`, `triangle` and
`sawtooth` evaluate a negative normalized time at `t < time_offset()`. Both auditors flagged
it and both said keep it out of DR-117, precisely because DR-117 restores the offset and a
correct offset is what makes this observable. Measured: `square(0)=+1` where the wrapped
`tau=0.75` demands `-1`, `sawtooth(0)=-0.25` where it demands `+0.75`, and at offset `0.95 T`
the triangle returns `+1.8` for an amplitude of 1 — outside its own declared range.

**Stale claims corrected** in `todo/ngspice_parser_plan.md`, which recorded the same
"latent for sine" reading in two places.
