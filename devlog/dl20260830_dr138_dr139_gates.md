## The owed DR-138 gate was mis-scoped, and the re-scope is the result

The controller's coupled circuit sequence is call-for-call what the existing unit
test already runs. Reject is `reset_timestep()` -> `mCircuit->shift_back()`
(`cl_FEM_Controller.cpp:2808-2810`); the retry is `set_timestep` -> `shift` ->
`compute_MNA_matrix` (`:247-249`, `:381-383`). `take_step` in
`tests/circuit/test_ElectricalCircuit.cpp:93-99` is that same triple, and
`RLCRingAcrossRejectedStep` drives reject-then-two-half-steps. So the inductor
arithmetic a coupled A/B would re-measure is already green at 1e-3 on a 1 A carrier.

What the coupled path genuinely adds is the **FEM leg**, and it carries the same
shape as the original defect. `ElectricalCircuit::shift_back()` handles
`TERMINALPAIR` in the inductor/capacitor arm — revert the registers, then
`compute_current()` — and `FEMTwoTerminals::compute_current()` reads `mIn`, which
`shift_back()` does **not** revert (`cl_FEMTwoTerminals.cpp:28-30`, `:46-50`).
Derived state recomputed from un-reverted scratch: DR-138 exactly.

Static trace says it is not live: `mIn` is written only through `set_IV` <-
`ElectricalCircuit::set_current_and_voltage` <- `Controller::compute_circuit_current()`
(`:3006`) <- one call site, inside `Controller::finalize()` (`:3049`), the accept path.

## (a) The FEM leg, executed

Scratchpad probe (not in the tree), linked against the prebuilt `libbelfem.a`,
syntax-gated first with the module's own flags under `-Werror`. Resonant RLC ring
with a `FEMTwoTerminals` across the load; controller-parity stepping; a FEM
surrogate whose branch current depends on the accepted terminal voltage, so the
loop is genuinely closed.

```
reference twin steady-state |I_L| peak : 1.497257e+00 A
                                      I_L max|B-A|   I_fem max|B-A|
B  accept-only set_IV    (tree today) : 8.241451e-06   3.727577e-04
C1 converged-rejected mIn (weak ctrl) : 1.611603e-05   3.786640e-04
C2 diverged mIn           (neg ctrl)  : 3.927533e-04   3.404384e-02
B  < 1e-3 : PASS      C2 > 1e-3 : PASS
```

**Finding: the FEM leg is safe entirely because `set_current_and_voltage` is
accept-only. `shift_back()` gives `mIn` no protection whatsoever.** C2 poisons
`mIn` with a diverged branch current before `shift_back()`; it survives the
rollback into the retry's MNA stamp and moves the terminal current 91x more than
the faithful case. Latent fragility, not a live defect — but any future path that
writes `mIn` on a non-accepted attempt re-creates DR-138 on the FEM leg silently.

**Method note worth keeping:** the first negative control (C1 — a converged-but-
rejected attempt writing `mIn`) read FAIL, because such an attempt differs from
the retry only by truncation. The controller rejects **non-convergence**, so the
diverged iterate is the honest control. A negative control that cannot fail is
not a control.

**DR-139's gate PASSES.** No `SpMatrix` appears in any leak record. All 34
definitely-lost blocks (19,221 bytes) are OpenMPI/PMIx allocations made inside
`MPI_Init` — each is either frameless or bottoms out at

an explicit deliberate-leak probe was offered and not built.

### The by-catch: heap buffer overflow in `ElectricalCircuit::compute_adjacency()`

22 error contexts — **14 invalid writes, 8 invalid reads, every one in BELFEM
code**, no MPI noise in the error class.

Node vertex containers are sized at `cl_ElectricalCircuit.cpp:462` as
`tNumNodesPerNode(n)+1`, where the count at `:449-453` admits only
RESISTOR/CAPACITOR/INDUCTOR/TERMINALPAIR/DIODE/SUPERCONDUCTOR neighbors and the
`+1` covers the self-insert at `:472`. Line `:534` then inserts the
**unknown-current vertex** (voltage source, current source, switch) into that same
node container — and that insert is **never counted**.

Arithmetic matches the record exactly. `NgspiceFactory.SolvedDcDivider`
(V1 + R1 + R2, no switch): node `in` has 1 neighbor + 1 self -> `malloc(2*8)` =
16 bytes; inserts are self, `mid`, V1 -> index 2 written ->
*"Address ... is 0 bytes after a block of size 16 alloc'd"*, allocated at
`cl_Graph_Vertex.cpp:57` from `:462`.

Not universal because the sizing loop at `:449-453` counts DUPLICATES while the
population loop dedups via `unique()` at `:496`; circuits with parallel R/L/C
over-allocate and the slack absorbs the uncounted source insert. It fires at any
node with an unknown-current component attached and no parallel-component slack.

Second, independent shortfall: the switch self-insert at `:541` is not counted in
`tNumNodesPerUnknown` at `:507-517`. That one explains the four `Switch*` tests.
**A first diagnosis blamed only the switch case and was refuted by the DC divider
having no switch** — recorded because the switch path is the seductive reading.

Two notes:

- `BELFEM_ASSERT` in `Vertex::insert_vertex` **cannot** catch this: it checks
  `mVertexCounter < uint32 max`, the counter width, not the container capacity.
  It guards an invariant nothing is near while the real bound goes unchecked.
- Consistent with the DR-110 ruling rather than a counter-example: under
  "callers allocate precisely what they append" this is a caller bug, so the fix
  belongs in the two sizing loops, not in a capacity member on `Vertex`.

**98/98 tests pass while the code writes out of bounds**, and release builds do it
silently into adjacent heap. Another instance of the suite not being what finds
our defects.

Not filed and not fixed — executable code, so it wants the full
plan+audit -> code+audit round, and whether it extends DR-139 or takes its own row
is Christian's call.

## The overflow FIXED — plan+audit -> code+audit, both vendors, no defects found

### What the plan round changed

**Claim 2 was REFUTED the same way by both vendors, independently.** My account —
"the sizing denylist over-counts, and that is the only reason this does not
overflow everywhere" — is wrong. The denylist/allowlist difference is a
**SUBSTITUTION, not an over-count**: a voltage source or switch contributes its
other node to the size and contributes nothing to the neighbor inserts, then
`(*)` inserts the branch vertex instead. Net zero when that other terminal is
live; a straight **deficit of one when it is tied to ground** — which is
`SolvedDcDivider`, `create_vr_circuit` and `create_rlc_circuit` node 0. The
`unique()` padding on parallel passives is the real reason some circuits survive.

Grok additionally corrected two of my counts: the switch-diagonal overflow at
`:541` hits **three** tests, not four ( `NgspiceFactory.SwitchBeforeVoltageSourceAccepted`
never calls `compute_MNA_matrix` ), and `SwitchBeforeVoltageSourceAgrees`
overflows **both** containers, so the switch tests are not explained by the
diagonal alone. Verified in the dump before adopting.

Adopted from the round: keep the allowlist membership unchanged ( `TERMINALPAIR`
is a structural zero in `mMNA` but load-bearing for pattern identity — "cleaning"
it would change nnz ); never `unique()` the unknown-current attachments ( two
sources on one node are two distinct branch dofs ); never fold branch-vertex
indices into the neighbor cell ( **the first voltage source carries index
`mNumberOfNodes-1`, the same number as ground**, so `mNodes( index )` would
silently resolve to ground ); add a post-fill `BELFEM_ASSERT` against the local
size, since `Vertex` holds no capacity member and `insert_vertex` guards only the
counter WIDTH; and leave the pre-existing `max( empty Vector )` death for
`mNumberOfNodes == 1` alone rather than widen scope.

### Landed

`compute_adjacency()` now computes the neighbor set ONCE into
`Cell< Cell< index_t > >`, sizes each node container as
`1 + unique(allowlist neighbors) + unknown-current attachments`, and populates
from the same sets. Branch containers gain `+1` for the switch diagonal.
`tNumNodesPerNode` and its vestigial `fill(0)` are retired. +93/-41.

Code audit: **both vendors APPROVE, no defects in the landed code.** Nits only —
a theoretical `size_t`->`uint` narrowing at `init_vertex_container` ( unreachable
below 2^32 vertices on one node, already outside `Vertex`'s own contract ), and
the deliberate `Cell<uint>` / `Vector<uint>` inconsistency ( new counter follows
the documented container rule; the pre-existing one left alone to keep the diff
minimal ). Vendors split on that one in round 1 and both called it a non-blocker.

Also landed: the `mJ` nulling. Codex called its comment inaccurate; Grok
adjudicated the mechanism the other way and the comment was rewritten to state
both halves — the delete prevents a leak on retry, the nulling prevents that
delete from leaving a dangling pointer if the following allocation throws, which
the destructor would free a second time. The path needs TWO throws to reach.

## An adjacency regression test — and what mutation testing said about it

`tests/circuit/test_CircuitAdjacency.cpp`, 15 cases, plus two const accessors
( `number_of_graph_vertices()`, `degree_of_graph_vertex()` ) as the minimal seam.
Full plan+audit -> code+audit round, both vendors.

**The test cannot validate the DR, and says so in its own header.** The defect
under-sized the containers while inserting the same set, and degrees are
INSERTION counts, so a surviving process reports them unchanged either way. The
gate stays valgrind.

**Every expected vector was MEASURED, not derived** — a hand-derived expectation
is exactly what a test would enshrine if wrong. Both auditors then re-derived the
full set independently from the insert rules and agreed on all of them.

### Mutation testing, which is the only reason to believe the test

| drift | release ( NDEBUG ) | debug ( DEBUG ) |
|---|---|---|
| allowlist ( changes INSERTS ) | CAUGHT, one named test fails | caught |
| switch diagonal, SIZING only | process dies, exit 59, no diagnosis | CAUGHT by the post-fill assert |
| wrong dedup, SIZING only | **PASSES 14/14, exit 0 — INVISIBLE** | CAUGHT by the post-fill assert |

**Consequence: `make check` must run in the DEBUG tree ( `build/` ) for this
guard to have teeth.** In `cmake-build-debug` a sizing-only drift that
under-allocates every node sails through green — which is also the retroactive
explanation for how the original overflow survived a green suite.

### What the audits caught in MY work

- **A real defect in the test.** `AllPassiveTypesAreNeighbors` put C, L, D and
  SC all in PARALLEL on one node pair, so `unique()` collapsed them to a single
  neighbor and dropping `DIODE` or `SUPERCONDUCTOR` from the allowlist left the
  degrees unchanged — the test could not see it. Rewritten as a CHAIN with each
  type on its own pair, `[2,3,3,3,2]`; the DIODE mutation now fails as it should.
- **"whether the switch is open or closed" was untested** — all three switch
  cases passed `create_switch(true, …)`. A future `is_closed()` guard around the
  diagonal would have stayed green. Added the open-switch twin, same `[3,2,3,1]`.
- **"a changed filter fails here" was too broad** — refuted by my own M3.
- **"describing different graphs" was FALSE**: the divider and the
  parallel-passive case produce the SAME graph, not merely the same degree
  sequence. The surviving valid point is that nnz ( the SUM of degrees ) cannot
  separate `[3,2,1]` from `[2,2,2]`, and that a degree sequence does not prove
  graph identity.
- **"one slot short" and "all of these would have passed pre-fix" were wrong**:
  two sources on one node were short by TWO, a fully grounded source was not
  short at all, and a fully grounded switch wrote its diagonal into a NULL
  buffer. The old 98-green suite simply did not contain these cases.
- **"re-derived by two auditors"** over the whole file was narrowed — T1-T6 were
  derived before measurement; the rest were auditor recommendations measured
  afterwards.
