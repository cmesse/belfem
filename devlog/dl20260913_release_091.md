## Second commit: `-Wfloat-conversion` and the cohomology sweep it triggered

Christian asked for a compile-time tripwire for the `abs` class of defect. `-Wfloat-conversion`
was added to `config_gcc.cmake` as warning-only (`-Wno-error=float-conversion` under GCC's
`-Werror`; Clang has no global `-Werror`). Before enabling it, Christian asked that the
cohomology module be checked for breakage: a syntax-only pass over the homology sources with the
flag found two warning sites in the closed core (`fn_Smith.hpp:181` `floor()` of an `int/int`
quotient; `Matrix<int>(n, m, 0)` hitting the fill constructor's `const real aValue`) plus
`cl_Homology.cpp:364` (`real tCoeff = ±1.0` into an `int` parameter, found after the edits).

**Christian explicitly approved edits inside the AI-closed cohomology core for this session**
(protocol §7.1 override, owner's call): `abs` -> `std::abs` at every integer site
(`fn_Smith.hpp` x4, `cl_SimplicialComplex.cpp` x6, `<cstdlib>` added), and `floor(a/b)` -> `a/b`
at `fn_Smith.hpp:181,195` and `fn_Smith.cpp:70`. The fill constructor in `cl_AR_Matrix.hpp` /
`cl_BZ_Matrix.hpp` now takes `const T aValue`. `cl_Homology.cpp:364` was NOT edited (outside the
reviewed patch); it is the one `-Wfloat-conversion` warning left in the closed core.

Behaviour preservation, verified statically: the Smith templates are instantiated only with
`Matrix<int>` (`mD` in both `Cohomology` and `Homology`, `tTransInv`), so `int/int` truncates
before `floor()` sees an integral double — `floor` was an identity. Christian's reading, agreed:
truncation toward zero is the sign-symmetric choice (trunc(-x) = -trunc(x)); true floor division
would be asymmetric and would change the transformation matrices, hence the generator
representatives, for negative quotients. Not a patch-release change; noted for Gregory.

Blind jury (Codex gpt-5.5 read-only; Grok devbox with read-only tool allowlist, same brief):
all four claims VERIFIED by both. Grok's one nuance, accepted: under `USE_MKL_64BIT_API`
(`index_t` = `uint64_t`) the old constructor pushed `gNoIndex` = 2^64-1 through a `double` that
cannot hold it (`cl_Mesh_ConnectivityCalculator.cpp:1152`, UB); the new one passes it through
exactly. So on that configuration the patch fixes a latent defect rather than being bit-identical.
Both auditors: no other defect. Syntax check of the four edited homology units with the flag:
0 errors, both original warnings gone.

Pipeline 28 (the first release commit `fa207fa3`, before this change) finished 4/4 green
(jobs 96-99: 803/1300/818/1576 s) — the executable gate for the `std::abs` fixes on Rocky.
Christian's own Ubuntu 24.04 `make check` passed too.
