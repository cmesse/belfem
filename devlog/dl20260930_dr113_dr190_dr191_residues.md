## Summary

Nine rows were open, none `[F]`. The cheapest clean retirement was the residue set filed two days
earlier: the dangling `IWG::mField` after a caught `create_field` refusal (DR-190), and on DR-191 the
unnamed `dmumps_` valgrind context, the test window that admitted any switch inside `( x/4, 2x )`, the
tin cubic's sign, and the nine-metal NaN-fill question. DR-113 needed no code: its status cell still
said `make check` owed for the DrainCheck tests, while the 17/17 of 2026-09-29 had run `commmpi_np2`
and `commmpi_np4` with those tests in the binary.

Three things changed the shape of the round. The `dmumps_` field was **named from the driver source**
instead of recollected: MUMPS 5.9.1 reads `KEEP(40)`, its last-phase tag, at the top of `JOB = -1`
(`OLDJOB = KEEP(40) + 456789`, refusing `-1, 1, 2, 3` with `INFO(1) = -3`) before `DMUMPS_INI_DRIVER`
sets any default, and the user guide asks the caller to set only `JOB`, `PAR`, `SYM` and `COMM`; a
fresh Fortran `allocate` leaves it undefined, so the wrapper zeroes it on every slot of a freshly
allocated pool and nowhere else — a clear on every create would hide the driver's own reuse check,
since `JOB = -2` writes `-2 - 456789`. The nine-metal NaN fill was **replaced by a form that makes the
defect impossible**: four metals already assign their switch vector with braces, so the five that
sized and stored now do the same. And the plan jury (Grok) found that **`Silver::create_kohler` had
been wrong since it was written**: block 1 computed the longitudinal cubic and stored it into `q0`,
block 2 computed the transversal cubic with block 1's derivatives, and block 3 recomputed the
longitudinal cubic with `d2dgw2` where `d2gdx2` belongs and wrote `p0( 0 )` followed by `q0( 1..3 )`.
So `p0( 1..3 )` were never written and `q0( 1..3 )` carried longitudinal coefficients, below
`BS = e^{w0} = 4.77e-3` — the stationary point of `q1 − p1`, not a crossing, as both auditors caught
in the code round after I had called it one. Silver is a tape-stack component in seven shipped
decks. Christian ruled it repaired in this round; the same C2 match as lead and tin, block 3 deleted.

Why valgrind never saw the silver defect, when it had caught lead's: `Cell::set_size` is
`std::vector::resize`, which value-initializes each `Vector`, and `Vector() = default` is not
user-provided, so the whole object including Armadillo's local buffer is zeroed first. The unwritten
coefficients were deterministic zeros, and the shipped longitudinal low-field curve was
`p0( 0 ) · BS³` alone. The gate showed exactly that: the new test red on HEAD for both silver cases,
valgrind silent.

## DR-191

Four residues paid, one widened. The `KEEP(40)` clear (above; 1 → 0 contexts). The branch test now
samples `x/4`, `0.9x`, `1.1x`, `2x` against branch-specific oracles at `1e-10`, each with a
separation self-check (`1e-2` far, `1e-6` near; the near gaps are `7e-5` / `6e-5` for lead,
`4e-5` / `3e-5` for tin, `1.2e-3` / `6e-4` for silver), so a switch stored outside `( 0.9x, 1.1x )`
sends one sample to the wrong oracle — Codex showed `1.05x` still passes, and the comment now says
the interval, not "anywhere else than `x`". The oracle is a general log polynomial (Horner for g, g',
g''; `F'' = F ( g'² + g'' − g' ) / x²`), which is what admitted silver's degree-3 transversal fit.
The tin longitudinal cubic below `B·S ≈ 4` (`−2.9e-4` at 1 T, `S = 1`) is left and accepted by
ruling; Codex corrected the plan's "below 4 T" to the scaled field `B·S`, which the database build
reaches. Operational consequence, on the closed row in bold: every `Pb*Sn*_RRR*.hdf5` and every
`silver_RRR*.hdf5` cache written before these fixes keeps a wrong table, because
`rho_database_is_current` accepts any file with an `RRR` link.

Recorded on the closed row from the driver read (Grok's risk, sharpened by me): `DMUMPSID` zeroes
`KEEP` and writes `KEEP(40) = -1 - 456789`, so a `JOB = -1` that fails after reaching the defaults
leaves `OLDJOB = -1`, which the entry check refuses on the next `JOB = -1`; the wrapper's rollback
runs no `JOB = -2`, so such a slot refuses every later re-init. Pre-existing, no in-tree caller
reaches it.
