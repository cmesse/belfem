## Module Overview

The interpolation module provides shape functions and their derivatives for all element types in BELFEM. It is ~19K lines organized into four layers:

| Layer | Content | Test Priority |
|---|---|---|
| **Lagrange shape functions** | ~30 element types: LINE2–5, TRI3/6/10/15, QUAD4/8/9/16, TET4/10/20/35, HEX8/20/27/64, PENTA6/15/18, PYRA5/13/14 | **Highest** |
| **Non-Lagrange shape functions** | Bernstein (LINE3, TRI6), Hermite (BEAM=LINE2→4 DOFs, PLATE=QUAD4→16 DOFs) | High |
| **Infrastructure** | `InterpolationFunctionFactory`, `IntegrationData`, `fn_num_nedelec_dofs`, `initialize_shape_function` | High |
| **Bubble functions** | Facet-based for TRI3/6, TET4/10 (per-facet variants A/B/C/D) | **Low — see note** |
| **Nédélec edge functions** | `EdgeFunction` hierarchy: EF_TRI3, EF_TRI6, EF_TET4, EF_TET10, EF_QUAD4TS/3 | **Deferred** |

### Common API

Every `InterpolationFunction` provides:

| Method | Signature | Output Size |
|---|---|---|
| `param_coords(aXiHat)` | → `Matrix<real>` | D × B |
| `N(aXi, aN)` | → `Matrix<real>` | 1 × B |
| `dNdXi(aXi, adNdXi)` | → `Matrix<real>` | D × B |
| `d2NdXi2(aXi, ad2NdXi2)` | → `Matrix<real>` | D₂ × B (see convention below) |
| `number_of_bases()` | → `uint` | B |
| `number_of_dimensions()` | → `uint` | D |
| `interpolation_order()` | → `InterpolationOrder` enum | — |
| `interpolation_type()` | → `InterpolationType` enum | — |
| `geometry_type()` | → `GeometryType` enum | — |
| `element_type()` | → `ElementType` enum | — |

### Second-Derivative Row Convention

The `d2NdXi2` output rows follow a Voigt-like convention:

| Dimension | Rows (D₂) | Meaning |
|---|---|---|
| 1D | 1 | ∂²/∂ξ² |
| 2D | 3 | ∂²/∂ξ², ∂²/∂η², ∂²/∂ξ∂η |
| 3D | 6 | ∂²/∂ξ², ∂²/∂η², ∂²/∂ζ², ∂²/∂η∂ζ, ∂²/∂ξ∂ζ, ∂²/∂ξ∂η |

**VERIFIED 2026-03-22:** Row counts confirmed (1D=1, 2D=3, 3D=6) by inspecting `set_size` calls in LINE2/3, TRI3/6, QUAD4/9, TET4/10, HEX8/27, PENTA6. The 3D ordering follows the classical Voigt stress convention `{11, 22, 33, 23, 13, 12}` → `{ξξ, ηη, ζζ, ηζ, ξζ, ξη}`. Verified analytically against HEX8 and PENTA6 shape function second derivatives.

## Important Notes

### NOTE-I1: Bubble Functions Are Interim

The current bubble functions use a face-bubble approach (see `slave_side_enrichment.md`). This approach is acknowledged as insufficient for inf-sup stabilization — it does not enrich edge traces. The real enrichment will use PUM-style TET10 mid-edge functions generated by MATLAB. **Tests for bubble functions should be smoke-level only** — verify the factory creates them without crashing and that they have basic sanity properties. Do not invest in extensive bubble coverage.

### NOTE-I2: Bernstein Factory Returns Lagrange for Linear Elements

`create_bernstein_function(LINE2)` creates a `LAGRANGE` template (not `BERNSTEIN`). Same for `TRI3`. This is presumably intentional (linear Bernstein ≡ Lagrange), but `interpolation_type()` will return `LAGRANGE`, not `BERNSTEIN`. The test should document this behavior.

### NOTE-I3: Nédélec Edge Functions Require fem::Element

`EdgeFunction` subclasses (EF_TRI3, etc.) require `link(fem::Element*)` with real geometry and edge directions before `E()` or `C()` can be called. Testing them in isolation requires building a mesh element with nodes — this is integration-level testing. **Deferred to a future plan** except for `fn_num_nedelec_dofs` which is trivially testable.

### NOTE-I4: IntegrationData Depends on Integration Points

`IntegrationData::populate()` calls into the integration point machinery (`fn_intpoints`). Testing IntegrationData thoroughly belongs in `tests_12_integration.md`. This plan includes only a thin consistency check.

### 2.1 Interior Test Points

Claude Code should define interior test points for each geometry type:

| Geometry | Representative interior point |
|---|---|
| LINE | ξ = 0.3 |
| TRI | ξ = 0.2, η = 0.3 |
| QUAD | ξ = 0.3, η = -0.2 |

| Test Name | What It Verifies |
|---|---|

| Test Name | What It Verifies |
|---|---|

| Test Name | What It Verifies |
|---|---|
| `NShapeCorrect` | `N` output is 1 × B |
| `dNdXiShapeCorrect` | `dNdXi` output is D × B |
| `d2NdXi2ShapeCorrect` | `d2NdXi2` output has B columns and the correct number of rows per the Voigt convention |

### 2.6 Finite-Difference Derivative Consistency `[semantic]`

This is the single highest-value numerical check. For each Lagrange element, at the interior test point:

| Test Name | What It Verifies |
|---|---|
| `dNdXiMatchesFiniteDifference` | For each basis i and direction d: `dNdXi(d,i) ≈ (N(ξ+h·eₐ)(0,i) - N(ξ-h·eₐ)(0,i)) / (2h)` |
| `d2NdXi2MatchesFiniteDifference` | For each basis i and each d2NdXi2 row: the second derivative matches finite differences of dNdXi |

Use `h = tFD = 1e-7` and tolerance `tTolFD = 1e-6`.

### 2.7 Polynomial Completeness `[semantic]`

For each geometry family, verify that an element of polynomial order p exactly reproduces polynomials of degree ≤ p.

| Test Name | Geometry | Function | Element | What It Verifies |
|---|---|---|---|---|
| `LinearFieldLine` | LINE | f(ξ) = 3ξ + 2 | LINE2 | Exact interpolation at 5 interior points |
| `QuadraticFieldLine` | LINE | f(ξ) = 4ξ² - ξ + 1 | LINE3 | Exact interpolation |
| `LinearFieldTri` | TRI | f(ξ,η) = 2ξ + 3η + 1 | TRI3 | Exact interpolation |
| `QuadraticFieldTri` | TRI | f(ξ,η) = ξ² + 2ξη + η² - ξ + 1 | TRI6 | Exact interpolation |
| `LinearFieldQuad` | QUAD | f(ξ,η) = 2ξ - η + 5 | QUAD4 | Exact interpolation |
| `BilinearFieldQuad` | QUAD | f(ξ,η) = ξη | QUAD4 | Exact interpolation (bilinear completeness) |
| `LinearFieldTet` | TET | f(ξ,η,ζ) = ξ + 2η + 3ζ + 1 | TET4 | Exact interpolation |
| `QuadraticFieldTet` | TET | f(ξ,η,ζ) = ξ² + ηζ + η - 1 | TET10 | Exact interpolation |
| `LinearFieldHex` | HEX | f(ξ,η,ζ) = ξ - η + 2ζ + 3 | HEX8 | Exact interpolation |
| `TrilinearFieldHex` | HEX | f(ξ,η,ζ) = ξηζ | HEX8 | Exact interpolation |

**Implementation pattern:** Sample the function at param_coords nodes, then verify that ΣᵢNᵢ(ξ)·fᵢ = f(ξ) at several interior evaluation points.

## 8. Implementation Notes for Claude Code

1. **Use the factory for all shape function creation.** Never instantiate `InterpolationFunctionTemplate<>` directly in tests — always go through `InterpolationFunctionFactory`.
2. **Memory ownership:** The factory allocates on the heap. Every created function must be deleted by the test. Consider using `std::unique_ptr` in test fixtures for automatic cleanup.
3. **Parameterized tests are essential.** The Lagrange catalog has 26+ entries. A `TEST_P` with a struct containing `{ElementType, expectedB, expectedD, expectedOrder, expectedGeom}` is far more maintainable than 26 individual tests.
4. **Finite-difference helper:** Implement a test-local helper that perturbs one coordinate, re-evaluates N, and computes the central difference. Apply it uniformly to all elements.
5. **Polynomial completeness pattern:** For each test, compute nodal values from the known polynomial at `param_coords`, then verify interpolation at multiple interior points. This exercises both `param_coords` and `N` together.
6. **Asymmetric test points.** Avoid ξ = 0 for interior tests — use values like 0.3, -0.2 to break symmetries that could mask index errors.
7. **Hermite DOF ordering.** The beam element interleaves value/derivative DOFs: (w₁, θ₁, w₂, θ₂). The plate element has 4 DOFs per corner node: (w, ∂w/∂ξ, ∂w/∂η, ∂²w/∂ξ∂η). Verify by inspecting param_coords and N at the corners.
8. **The d2NdXi2 Voigt convention** is not documented — verify the row ordering empirically for 2D (3 rows) and 3D (expected 6 rows) by checking which entries are nonzero for known elements.
9. **Bernstein vs Lagrange comparison:** At a non-nodal point, Bernstein LINE3 and Lagrange LINE3 should produce different N values but the same interpolated result for the same polynomial (since they span the same polynomial space). This is a powerful consistency check.
10. **IntegrationData dust cleanup.** The `evaluate_function()` method zeroes N entries below `1e-16` and dNdXi entries below `BELFEM_EPSILON`. If comparing IntegrationData cached values to direct function calls, account for this threshold difference.
