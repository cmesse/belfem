# Thin-Shell Normal-Field Recovery Next to an h-Conductor Volume

> **CLOSED 2026-09-03** (todo/ currentness sweep, round 3): the h_n recovery defect is fixed with six tests; G7 (transport current as a winding) is a separate question about the corc_solder terminal model, not this defect. Status lines and checkboxes below are as they stood at closure and are not maintained.

**Date:** 2026-09-01
**Purpose:** A thin shell whose neighboring volume is an h-conductor (corc_solder: the solder annulus) gets its normal field h_n from `−∇φ` of that volume, although the volume has no φ dofs — the nodal `phi` there is bookkeeping (0 on solder-only nodes, the bore gauge level on nodes shared with the bore air). Result: helical strips of ~1500 A/m fictitious normal field on the tape sheets at 0.15 A, written to the exodus H/B and fed to jc(|B|, β, T) in the solve. Give the recovery a per-side dispatch (φ-side: −∇φ; h-side: n·(E·h_edge) of that element) in the solve function and its postprocessor twin, and settle the two questions the round left open (frozen transport current, unpinned bore).
**Module:** `src/fem/kernel` (`cl_FEM_Calculator.{hpp,cpp}`), `src/fem/maxwell` (`cl_MaxwellPostprocessor.cpp`, `cl_MaxwellFactory.cpp`), `src/mesh/en_DomainType.hpp`
**AIs involved:** Claude (diagnosis + plan), Codex-sol + Grok (blind jury, 2026-09-01), Fable (implementation, planned)

## 6. R1 findings (Fable, 2026-09-01, reviewed — static trace only, nothing built or run)

Numbering below is referenced by the R2 design in §9.

**6.1 Facet master/slave rule for shells.** `cl_MaxwellFactory.cpp:1526-1544` compares the two volume blocks' `DomainType` as integers and calls `tFacet->flip()` when master < slave (`cl_Facet.cpp:90-98` swaps master/slave and face ids, recomputes the orientation), so the higher enum value is always master. Values (`en_DomainType.hpp:27-37`): Air 1, Buffer 2, Ferro 3, Coil 4, Conductor 5, ThinShell 9. corc_solder (`examples/corc_solder/input.conf:184-196`: blocks 1, 3 air; block 2 `conductor : solder`) therefore has solder as master on every tape facet — as the `.bfm` showed. A conductor can be the *slave* of a shell facet only when the other side is also ≥ Conductor, i.e. a shell soldered on both sides. Confidence: high.

**6.2 Layer element → tape facet.** `BlockData::link_thin_shell_facets_serial` (`cl_FEM_DofMgr_BlockData.cpp:468-486`) gives the k-th element of every layer block `set_facet( tShell->facets()( k ) )`; the parallel twin (`:522-531`) broadcasts the (element, facet) id pairs to every rank, aura copies included. `compute_hn` reaches that facet through `this->element()->facet()` (`cl_FEM_Calculator.cpp:1984`). Confidence: high.

**6.3 The tape sideset in the DofManager.** `IWG_Maxwell::init_activation_maps` puts `DomainType::ThinShell` sidesets in `GroupActivationMode::GeometryOnly` (`cl_IWG_Maxwell.cpp:134`; `en_FEM_GroupActivationMode.hpp:28`): calculators, no dofs. Its facet elements link no dofs (`cl_FEM_Element.cpp:318-323`, mode `Inactive`), but carry `mMaster`/`mSlave` = the volume Blocks' fem elements looked up by id (`cl_FEM_Element.cpp:100-115`), and the Block element map includes aura elements (`cl_FEM_Group.cpp:101-117`). **Aura fem elements have no dofs** (`cl_FEM_Block.cpp:72-81` → ctor `cl_FEM_Element.cpp:38-49`, "aura elements carry no dofs, but the postprocessors evaluate their nedelec fields") but do compute edge directions. Confidence: high.

**6.4 What the tape sideset's Calculator can evaluate.** `Calculator::allocate_memory` (`cl_FEM_Calculator.cpp:944-1100`): because `all_fields()` contains `edge_h` under h-φ, a sideset calculator gets master edge functions per master facet index, precomputed at `master_integration(s)->points()` (`:1053-1067`), and slave edge functions per (facet, orientation) permutation (`:1075-1093`), both of the volume types. `create_custom_vectors_and_matrices` (`cl_IWG_Maxwell.cpp:455-495`) adds `"nedelec_h"` sized by the **master** type's nedelec dof count (`:458-459`), plus `phi_m`, `phi_s`, `normal`, `hn`, `hm`, `hs`, `bn`. `Calculator::link( Element * )` (`cl_FEM_Calculator.cpp:1789-1901`) selects `mEdgeFunctionMaster` by facet index and links it to the master fem element (`:1875-1886`); the slave one by the flattened (facet, orientation) index (`:1888-1898`). After `get_normal_calculator` (`:1979-2029`, which calls `link( tFacet )` at `:2006`) the following are all evaluated at the same physical point k of the facet: `Em(k)`, `Es(k)` (`:3003-3032`), `Bm(k)`, `Bs(k)` (`cl_FEM_Calculator.hpp:1856-1885`, `inv(J) * dNdXi` of master/slave at the mapped point), and `normal(k)` (`.cpp:2521-2575` for TET masters, from master geometry only; its sign is irrelevant because `compute_hn` projects with `dot( hn, n ) * n`). Confidence: high.

## 9. R2 design — per-side dispatch of the normal-field recovery (Fable, 2026-09-01, PLAN-ONLY, awaiting Christian's approval before R3)

**9.1 The rule.** For each side σ ∈ {m, s} of a tape facet, with the side's volume element V_σ:

| side kind | test | trace |
|---|---|---|
| φ-side (Air, Ferro, Buffer, …) | `mesh->block( V_σ->block_id() )->domain_type() != DomainType::Conductor` | h_σ = −B_σ(k) φ_σ (unchanged) |
| h-side | `== DomainType::Conductor` | h_σ = E_σ(k) q_σ, q_σ(e) = `edge_h( V_σ->edge( e )->index() )` |

then, as today, h_n = ½ (h_m + h_s)·n n (O1: average). The dispatch key is the mesh block's `DomainType`, exactly `Conductor` — the only block type that is edge-interpolated *and* a volume neighbor a tape facet can have (`cl_IWG_Maxwell.cpp:63-79`: `edge_h` is pushed for `Conductor` only; `ThinShell`/coating blocks are layer or wall blocks, never a facet's volume side). Any other type keeps the φ path, so every existing deck (air/air, air/ferro shells) is unchanged by construction. Cost: two `mesh->block()` lookups per layer element per assembly, inside the existing k = 0 branch; no new allocation.

**9.2 Physics statement (to go into the code comment and the module doc).** Alves et al. 2022b derives the shell's normal field from h₀ = −∇φ⁻ and h_N = −∇φ⁺, both *nonconducting* sides; it supports the φ/φ construction only. The h-side rule rests on the continuum condition [n·B] = 0 across a current sheet: with μ = μ₀ in the shell's neighborhood, n·h is continuous too, so the conductor's own Nédélec trace n·(E q) is the correct normal field on that side. A magnetic conductor would need n·B = μ n·h continuity, i.e. a B-normal formulation — out of scope, guarded (9.4). The tangential part needs nothing: on a conductor side the shell edges hang on the volume edges with weight ±1 (§6.8), so the shell already carries the tet's tangential trace.

**9.3 Accessors (the R1 answer to "name the exact accessors").** On the tape-sideset calculator `tCalc` (the object `get_normal_calculator` returns, §6.4):

- new `Calculator::nedelec_data_master_h()` → fills `vector( "nedelec_h" )` (already master-sized, `cl_IWG_Maxwell.cpp:458-459`) with `edge_h( mElement->master()->element()->edge( e )->index() )`, e < master `number_of_edges()`;
- new `Calculator::nedelec_data_slave_h()` → same for `mElement->slave()`, into a new `"nedelec_h_s"` vector created in `create_custom_vectors_and_matrices` for sidesets with a slave, sized `number_of_nedelec_dofs( slave_type() )`;
- the existing dead `nedelec_data_linear_master` (§6.7) is removed in the same change (its only "consumer" would be the new code, and its buffer is wrong);
- `get_normal_calculator` keeps its signature, but reaches the sideset through `this->group()->parent()->sideset( id )` (§6.10a) so the fixture can call it; and returns the two side kinds through two new `bool &` out-parameters (`aMasterIsConductor`, `aSlaveIsConductor`) — no per-element string or map work beyond the two block lookups.

Mesh-field access is the *correct* live-dof access here, not a shortcut (§6.6): it is what `q()` reads, it is the only thing that exists for aura masters, and it is already synchronized to the workers after every update.

**9.4 Scope guard (nonmagnetic).** Setup-time, once, `BELFEM_ERROR`: when linking a ThinShell block group (`IWG_Maxwell::link_to_group`, the `DomainType::ThinShell` case at `cl_IWG_Maxwell.cpp:332-339`, or in `BlockData::link_thin_shell_facets` where the facets are handed out, §6.2), for every tape facet whose master or slave block is `Conductor`, require that block's material to be constant μ₀ — the same predicate MaxwellData uses to pick `compute_mu_0` (`cl_FEM_Calculator.cpp:243-249`, `tIsConstantMu0`). Message names the block and the shell. Follows the call-rate rule (setup code, always-active).

**9.5 Evaluation point — O4, logged, my recommendation stated.** In 3D the k = 0 point is the facet centroid, so both traces are exact at k = 0 (§6.5) and the change is a pure dispatch. In 2D the h-side trace at point 0 is off-centre by O(h). Options: (i) keep k = 0 everywhere (simplest, exact in 3D, the only tested case); (ii) integration-weighted mean of n·(E_σ(k) q_σ) over the facet's points for the h-side only (exact centroid value for a linear trace in any dimension; cost 7 small mat-vecs per layer element per assembly in 3D). **Decided 2026-09-01, Christian (revised): (ii) for the h-side, k = 0 for the φ-side.** The h-side loop runs over the facet's points inside the existing k = 0 branch: h_σ = Σ_k w_k E_σ(k) q_σ / Σ_k w_k, weights from the sideset calculator's own rule. Exact centroid value for a linear Nédélec trace in 2D and 3D, independent of the rule's point ordering; three products in 2D, seven in 3D, once per layer element per assembly; no allocation (the product lands in `hm`/`hs`). Note the 2D tapestack gate deck is air/air and never enters this branch — R5 covers the 2D h-side with a TRI3/LINE2 fixture case.

**9.6 The two twins become one trace.** Factor the per-side trace into one inline helper next to `compute_hn` (e.g. `compute_h_side( tCalc, side, isConductor, phi, k )` writing into `hm`/`hs`), used by `compute_hn` (solve) and by both postprocessor twins (`cl_MaxwellPostprocessor.cpp:514-560` conductor TS, `:838-870` superconductor TS), which keep their own μ handling unchanged: `bn = μ₀ · ½(h_m + h_s)·n n`, added to B, divided by the shell μ for H (`:545-556`). Single source of truth; R5 tests the helper once and the μ bookkeeping separately.
